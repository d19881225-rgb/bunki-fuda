# 分岐札 改善計画書・第2段階

作成日：2026年9月28日

対象：[公開サイト](https://d19881225-rgb.github.io/bunki-fuda/)

前段階：[基本機能の改善計画と実施結果](improvement-plan-2026-09-28.md)

## 結論：最初に何をするか

**「利用者の言葉で、既にある札を見つける」ことを最優先にする。**

全20枚の検索・カテゴリ絞り込み・手順チェックは公開済み。今回は作り直さず、検索の取りこぼし、0件時の行き止まり、再利用の手間を減らす。

札の追加や収益化を先行させない。既存20枚を使いやすくすることが、今回の改善目的である。

## 現状を確認して分かったこと

| 確認した事実 | 困ること | 判断 |
| --- | --- | --- |
| 公開サイトで「メール」は0件。受信箱の札は存在する | 内容があっても日常語では見つからない | 意味が合う検索語を札ごとに補う |
| 現在の検索は全角・半角を揃えるが、ひらがな・カタカナは別扱い | 「すまほ」「スマホ」などで結果が変わる | かな表記を揃えて検索する |
| 別カテゴリに該当札があっても、0件時は全解除しかできない | 検索語を消してやり直す必要がある | 検索語を残したまま全カテゴリへ広げる |
| 再利用はURLコピーか印刷のみ | 3手順を自分のメモへ残すには手作業が必要 | 手順・終了条件・出典をまとめてコピーできるようにする |
| 赤いボタン背景と本文色は約3.34:1、補助文字と黄緑背景は約4.17:1 | 一部の小さな文字が背景に対して薄い | 赤と補助文字の色を調整する |

色の比率は実装の色指定から計算した。アクセス数・利用率・売上は計測していない。検索語の補充は需要の実測ではなく、内容に基づく編集判断である。

## 実施順序と完了条件

| 優先 | 実施内容 | 完了条件 |
| --- | --- | --- |
| 1 | 20枚それぞれに内容と対応する検索語を追加。かな・全角半角を揃える。検索例ボタンと検索方法を表示 | 「メール」「めーる」「ﾒｰﾙ」で受信箱の札が見つかる。「片付け」で部屋の札が見つかる。複数語はすべてを含む札だけ返す |
| 2 | 0件時、別カテゴリに該当札がある場合は件数と探し直しボタンを表示 | 家事を選択して「メール」を検索した後、言葉を消さずに全カテゴリの受信箱の札へ移れる |
| 3 | 「3手順をコピー」を追加。コピー不可の場合は選択できる全文を表示 | タイトル・状況・所要時間・番号付き3手順・軽い代案・終了条件・正規URLをコピーできる。検索入力やチェック状態は含めない |
| 4 | 補助文字、赤い文字・ボタン、検索欄の例文を読みやすくする | 使用する主要な文字色と背景色の組み合わせを自動確認し、4.5:1以上。320px・390px幅で横スクロールなし |
| 5 | テスト、公開、結果記録 | 既存機能と新機能のテスト、ビルド、ESLintが通る。GitHub Actions成功と公開画面で動作を確認する |

## 変えないこと

- 既存20枚の内容とURL、検索・選択・チェックの基本機能は保つ。
- 新しい課金、アカウント登録、個別相談、外部AI呼び出し、広告、アクセス解析は追加しない。
- 検索やチェック内容を保存しない。検索語をURLへ入れない。
- コピーは利用者がボタンを押したときだけ実行する。コピー内容は自動送信しない。
- 無関係な検索語、病名、効果の保証、未確認の人気順位を加えない。

## 公開前の確認

1. 検索語の対応先と、全20枚・5カテゴリ・気力の候補を自動テストする。
2. コピー全文の形式と、クリップボード非対応・拒否時の代替を自動テストする。
3. ブラウザで検索例、かな検索、0件から全カテゴリへの復帰、手順コピーを操作する。
4. スマホ幅で新しいボタン・入力欄が収まることを確認する。
5. 全23ページの静的出力・正規URLを確認し、公開サイトへ反映する。

## 次の判断

今回の完了は操作と出力の確認で判定する。アクセス増・売上増を成果として報告しない。収益化は未設定であり、今回も追加しない。次回は利用状況の根拠が得られた場合に、検索語や札の追加を検討する。

## 実施結果

実装前に本計画書を作成し、以下を実施した。

| 項目 | 確認結果 |
| --- | --- |
| 日常語・かな検索 | 全20枚に対応語を追加。メール・めーる・半角表記・複数語の自動テストが通過。画面でも「めーる」で受信箱の札、「片付け」で洗濯と部屋の札が見つかることを確認 |
| 0件からの復帰 | 家事＋「めーる」で0件になった後、全カテゴリへ広げて検索語を残したまま1件表示になることを画面で確認 |
| 手順コピー | 全20枚について3手順・代案・終了条件・出典を自動確認。デスクトップと390px幅の画面でコピー成功表示を確認。コピー不可時の全文返却は自動テストで確認 |
| 読みやすさ | 補助文字を濃くし、赤色を調整。主要8組み合わせの文字・背景色が4.5:1以上になることを自動確認 |
| スマホ | 320px・390px幅でホームと詳細に横スクロールなし。検索例とコピー操作が折り返して表示されることを確認 |
| 品質確認 | 全20件の自動テスト通過。ビルド・TypeScript・ESLint通過。全23ページの正規URLと出力を確認 |
| 公開 | ローカル確認完了。GitHubへの反映と公開後の確認はこれから実施 |

クリップボードに入る全文の形式と欠落は自動テストで確認した。画面確認は成功メッセージと操作の確認であり、実端末全種類のクリップボードや共有先を検証したものではない。
